# 状态快照同步与底栏优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 状态变化时最多等待 2 秒读取当前 Email、5H 和 WK，并将它们与最新状态和 CTX 作为一条完整快照发布，同时降低 OLED 底栏的视觉干扰。

**Architecture:** `AccountResolver` 增加可等待的强制刷新接口，返回账号和 app-server rate limits；`MonitorService` 只对状态事件启用 2 秒门控并合并等待期间的状态，token 与 availability 保持现有路径。固件保留完整 state payload 渲染，只调整 footer 布局和闪烁判定。

**Tech Stack:** Node.js 20、TypeScript、`node:test`、MQTT.js、PlatformIO、Arduino、Adafruit SSD1306。

  const second = await resolver.refresh(target);

  assert.equal(second?.email, "new@example.com");
  assert.deepEqual(second?.quota, snapshot(30, 40));
  assert.equal(second?.stale, true);
});

- [ ] **Step 3: 实现状态发布门控**

- [ ] **Step 3: 实现超时和合并**

在 `MonitorServiceOptions` 增加内部测试注入项，生产默认值为 2000 ms：

```ts
refreshTimeoutMs?: number;
```

实现：

- 当前刷新保存 generation；
- 同一刷新期间状态事件只更新聚合器和 dirty 标记；
- 超时回调用 `{ ...currentAccount, stale: true }` 构造最新状态并发布；
- refresh 随后完成时发布纠正快照；
- refresh 结束后如 generation/线程/source 已变化，立即启动下一轮；
- `stop()` 清理定时器、递增 generation，并阻止后续回调发布。
