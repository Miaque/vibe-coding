# 文档协作指南

## 适用范围

本文件适用于 `docs/`。同时继承仓库根目录的规则。

## 文档分工

- `spec/` 记录目标行为、公共协议、架构决策、边界和验收标准，是实现语义的依据。
- `plans/` 记录实现顺序、文件范围和逐步验证方法，不替代规格。

规格回答“系统必须做什么”，计划回答“准备如何实现”。不要把临时任务进度写入
规格，也不要仅在计划中修改长期有效的协议。

## 编写约定

- 默认使用中文；代码标识符、命令、路径、环境变量和协议字段保持原文。
- 标题层级连续，表格和代码块保持可读，仓库内链接使用相对路径。
- 实施计划文件使用 `YYYY-MM-DD-简短主题.md` 命名。
- 命令必须注明执行目录，Windows 与 Unix 命令不兼容时分别给出。
- 引用源码行为前先核对当前实现；不要把计划中的示例当作已经存在的代码。
- 不伪造测试结果、设备验证、性能数据或已完成状态。

## 同步要求

修改 MQTT payload、环境变量、部署步骤、硬件接线、OLED 布局或验收标准时，
同步检查对应模块的 README、`.env.example`、测试和实现。文档若描述尚未实现的
行为，必须明确标注为目标或计划。
